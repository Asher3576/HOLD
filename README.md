# HOLD — 참은 것을 기록하는 투자 앱

> 수익률 대신, 계획대로 가고 있는지만 보여준다.
> 그리고 충동이 생기는 그 화면(남의 차트) 위로 직접 찾아간다.

투자 앱은 많다. 전략을 만들어주는 앱도, 자동으로 사고파는 앱도 있다.
그런데 계좌를 깎아먹는 건 대부분 전략이 아니라 사람이다. HOLD는 그 사람 옆에 선다.

---

## 크롬 플러그인 설치 (2분)

HOLD의 절반은 크롬 플러그인이다. 토스증권·네이버 증권·트레이딩뷰 같은 화면 옆에
사이드 패널로 붙어서 종목 인식, 실시세, 지지/저항, 손익비 점검, 모의 매수까지
그 자리에서 해결한다.

1. **[hold-plugin.zip 내려받기](https://github.com/Asher3576/HOLD/raw/main/hold-plugin.zip)** → 압축을 푼다
2. 크롬 주소창에 `chrome://extensions` 입력 → 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** 클릭 → 1에서 압축 푼 폴더 선택
4. 툴바 퍼즐(🧩) 아이콘에서 HOLD를 핀으로 고정 → 주식 페이지에서 HOLD 아이콘을
   누르면 오른쪽에 사이드 패널이 열린다

저장소를 클론했다면 zip 없이 3번에서 `extension/dist/` 폴더를 그대로 선택하면 된다.
크롬 웹스토어 등록은 진행 중이며, 등록되면 클릭 한 번으로 설치된다.

## 1. 해결하려는 문제

개인 투자자의 성과를 깎는 최대 요인은 전략이 아니라 행동이다.
감정에 의한 계획 외 매매, 하루 수십 번의 계좌 확인, 그로 인한 스트레스와 무리한 결정.

- 거래가 잦을수록 계좌가 녹는다는 통계는 있어도, 자동매매가 꾸준히 번다는 통계는 없다.
- AI로 전략을 아무리 잘 만들어도 결국 인간이 개입해서 계획을 깬다.
  부족한 건 전략이 아니라, 결정의 순간을 지켜주는 레이어다.
- 그리고 그 결정의 순간은 우리 앱 안이 아니라 증권사 화면과 차트 사이트에서 일어난다.
  앱만 만들면 충동의 현장에 없는 것이다. 그래서 크롬 플러그인으로 그 화면까지 간다.

## 2. 타겟 고객 — 두 유형

같은 문제("행동이 계좌를 깎는다")의 다른 단계에 있는 두 사람을 겨냥한다.

**유형 A — 덜 보고 싶은 사람 (앱의 주인공)**

- 매수는 하는데 "언제 팔지"에서 무너지는 사람
- 하루에도 수십 번 계좌를 열어보며 스트레스 받는 사람
- 손절/익절 계획을 세워놓고, 하락장이 오면 손절선을 옮기는 사람

이미 충동 매매의 비용을 몸으로 안다. 이들에게 필요한 건 분석 도구가 아니라
덜 보게 하는 마찰(금고)과, 참은 것이 자산이 되는 경험(열매)이다.

**유형 B — 어차피 매일 보는 사람 (크롬 플러그인의 주인공)**

- 차트를 열심히 보고 직접 분석하는 활동적 투자자
- 보는 것 자체를 문제라고 생각하지 않는 사람 — 못 보게 하는 제품은 애초에 선택하지 않는다
- 이들의 진짜 문제는 "봄"이 아니라 계획 없는 진입과 즉흥 매매

이들을 덜 보게 만들 수는 없다. 대신 보고 있는 그 화면 위에서,
진입하기 전에 손익비와 손절/목표를 세우게 한다. 보는 행위를 계획으로 변환하는 것.

두 유형은 하나의 퍼널로 이어진다. B는 크롬 플러그인(차트 도구)으로 들어와 계획 세우는
습관을 얻고, 계획이 쌓이면 앱의 A 루프(덜 보기 → 참기 → 복기)로 넘어온다.
플러그인이 유입과 현장 개입을 맡고, 앱이 절제와 기록을 맡는다.

## 3. 가설

1. 수익률 숫자를 숨기고 계획 대비 진행률만 보여주면, 계획 외 매매가 줄어든다. (A)
2. 매도 직전에 본인의 과거 매도 기록(판 뒤에 올랐던 비율)을 비추면, 충동 매도가 줄어든다. (A)
3. "참은 것"이 눈에 보이는 자산(열매)으로 쌓이면, 확인 중독이 수집 동기로 치환된다. (A)
4. 어차피 차트를 보는 사람에게 진입 직전 손익비 점검을 화면 위에서 제공하면,
   손익비 1 미만 자리에서의 진입이 줄어든다. (B)
5. 차트 도구로 들어온 사람도 계획이 쌓이면 절제 루프(앱)로 넘어온다 —
   플러그인 사용자의 알 생성이 앱 리텐션으로 이어진다. (B→A)

## 4. 해결 방식 — 결정 레이어

HOLD는 실거래를 지원하지 않는다. 주문 API도, 사용자의 증권사 API 키도 없다.
사용자는 계획을 "알"로 만들고, HOLD는 그 계획이 끝까지 가도록 결정의 순간마다 개입한다.
매수/매도는 전부 모의(시드 현금 1,000만)로 돌아간다.

### 앱

| 기능 | 설명 |
|---|---|
| 수익률 숨김 | 손절가를 0, 익절가를 100으로 놓은 진행률만 표시. 금액과 수익률은 금고 안에서만. |
| 금고 | 계좌 요약은 다이얼 금고 안에. 열어볼수록 다이얼이 오래 걸린다. 확인 중독에 마찰을 건다. |
| 목표 근접 블러 | 진행률이 목표에 가까워지면 숫자를 흐린다. "다 왔으니 팔자"를 방어. |
| 매도 개입 | 팔고 싶은 순간에 조언 대신 본인의 과거 매도 기록과 30일 후 결과를 보여준다. 반례도 반드시 함께. |
| 참은 기록(열매) | 개입 후 참으면 자동 저장. 30일 뒤 결과가 채점되어 열매가 익거나 시든다. |
| 계획의 세 가지 끝 | 만기 → 재계약 또는 완주. 손절선 작동 → 보험이 일한 것(실패가 아니다). 완주 → 부화, 도감 수집. |
| AI 뉴스 브리핑 | 보유 종목 헤드라인을 모아 부엉이가 한 문장으로 요약. 관련 기사만 태깅. |
| 3분 복기 | 최근에 끝난 계획을 두고 부엉이가 질문만 하는 대화형 복기. 감정과 이유를 분리해 기록한다. |

### 인사이트 프렌즈

세 마리가 역할을 나눈다. bull(황소)은 지킴이, bear(곰)는 걱정 담당, owl(부엉이)은 분석 담당.
캐릭터는 사용자를 절대 혼내지 않는다 — 곰의 걱정까지만 허용된다.

### 크롬 플러그인 — 충동의 현장으로

계획을 깨는 결정은 증권사 웹, 토스증권, 네이버 증권, 트레이딩뷰 화면에서 일어난다.
플러그인은 크롬 사이드 패널로 그 화면 옆에 붙는다.

플러그인은 "차트를 더 잘 보게 해주는 도구"가 아니라, 보는 행위를 계획으로 변환하는
장치다. 어차피 매일 차트를 보는 사람(유형 B)에게 진입 전에 손익비와 손절/목표를
세우게 하고, 그렇게 만들어진 계획이 앱의 절제 루프로 넘어온다.

- 보고 있는 페이지의 종목을 자동 인식(URL 어댑터 + 페이지 텍스트 폴백)하고 실시세를 띄운다
- 최근 일봉 스윙으로 지지/저항을 계산하고, 이동평균으로 단기/장기 추세를 사실 문장으로 보여준다
- 차트에 레벨을 긋는다 — 페이지 차트가 TradingView 기반이면 차트 안에 직접,
  아니면 축 눈금을 자동 인식해 화면 오버레이로, 그것도 안 되면 2점 수동 보정으로
- 손익비 계산기(가격과 % 양방향). 계산한 손절/목표가 그대로 모의 매수 계획으로 저장된다
- 웹앱과 같은 계정으로 로그인해서 모의 매수/매도가 앱 선반과 실시간으로 연동된다

모든 수치는 서버가 계산하고, 작도는 화면 좌표 계산일 뿐이다. 페이지 내용을 저장하지 않는다.

## 5. 하지 않는 것 (정책)

1. 사용자의 증권사 API 키를 절대 받지 않는다. 유출 리스크 자체를 만들지 않는다.
2. 실거래를 지원하지 않는다. 주문 실행 없음. 기록과 개입만.
3. AI는 절대 사라/팔라를 말하지 않는다. 자본시장법상 투자자문(수량·가격·시기 조언)의
   정의를 건드리지 않는다. 사실과 조건문만 쓴다. "저항 3번째 테스트, 거래량 감소"는 되고
   "지금 사세요"는 차단된다. AI 출력에는 지시어 필터가 걸려 있고, 걸리면 그 문장을 버린다.
4. 시세는 지연/정규장 기준을 쓴다. 실시간 호가 재배포 라이선스 리스크를 피한다.
5. 플러그인은 화면을 캡처하거나 저장하지 않는다. DOM에서 종목명 이상의 것을 읽지 않는다.
6. 캐릭터는 사용자를 비난하지 않는다. 실망 표정도 없다.

이 원칙들은 문서로만 있는 게 아니라 코드에 있다. `shared/src/compliance.ts`의 지시어
필터와 그 테스트가 CI에서 돌고, 원칙을 어기는 문장은 빌드가 막는다.

## 6. 아키텍처

원칙 하나로 정리된다: 수치는 서버가 결정적으로 계산하고, LLM은 문장만 쓴다.

```
web/               웹앱 (Vite + React 18 + TS) — 알·금고·도감·복기
extension/         크롬 플러그인 (Manifest V3, 사이드 패널, esbuild)
shared/            @hold/shared — 순수 로직 + Vitest (진행률·손익비·컴플라이언스 필터)
supabase/
├── migrations/    스키마 (plans, held_records, reviews, paper_accounts, app_cache)
└── functions/
    └── prices/    엣지 함수 하나에 라우트로 정리
                   /quotes /klines  한국투자증권(KIS) Open API 직접 연동 (국내+미국)
                   /news            구글뉴스 RSS 파싱 (키 불필요)
                   /brief /review   Gemini — 뉴스 요약과 복기 대사, 지시어 필터 통과분만
```

- 시세는 KIS Open API를 엣지 함수가 직접 호출한다. 접근 토큰(24시간 유효)은 `app_cache`
  테이블에 공유 캐시해서 서버 인스턴스가 몇 개 뜨든 하루 한 번만 발급한다.
- AI는 Gemini 플래시 라이트 계열을 우선 쓰고, 없는 모델이면 자동으로 다음 후보로 넘어간다.
  키가 없거나 호출이 실패해도 앱은 결정적 문구로 그대로 동작한다.
- 전 테이블 RLS. `app_cache`는 정책 없이 RLS만 켜서 서버 전용으로 잠근다.

## 7. 시작하기 (개발)

```bash
git clone <this-repo>
cd HOLD
pnpm install
pnpm dev        # 웹앱 — http://localhost:5173
```

- `web/.env`에는 Supabase 프로젝트 URL과 publishable 키가 들어 있다.
  publishable 키는 브라우저에 노출되도록 설계된 공개 키라 커밋해도 안전하고,
  배포(Vercel)도 이 파일로 빌드한다. 자기 프로젝트로 포크하면 이 두 값만 바꾸면 된다
  (`web/.env.example` 참고, 값은 Supabase 대시보드 → Settings → API).
- Supabase Edge Functions Secrets — `KIS_APP_KEY`, `KIS_APP_SECRET`(한국투자증권
  KIS Developers 앱키), `GEMINI_API_KEY`(선택, AI 브리핑/복기용).
  이 값들은 서버에만 있고 리포와 클라이언트에는 절대 넣지 않는다.

시크릿 키(secret / service_role)는 `.env`나 `VITE_` 변수에 넣지 말 것.
Vite는 `VITE_` 접두사 변수를 브라우저 번들에 그대로 노출한다.

### 명령어

```bash
pnpm dev        # 웹앱 개발 서버
pnpm test       # 전 패키지 테스트
pnpm typecheck  # 전 패키지 타입 체크
pnpm build      # 전 패키지 빌드
```

크롬 플러그인 설치는 문서 상단의 안내를 따르면 된다 (`extension/dist/` 빌드 결과와
`hold-plugin.zip`이 커밋되어 있어 별도 빌드가 필요 없다). 플러그인 코드를 수정했다면
`cd extension && node build.mjs` 후 `dist/` 안에서 zip을 다시 만든다.
